# Orca Delivery

`$orca-delivery <タスク文書>` など、Claude と Codex を使った一連の実行を明示的に依頼された場合に開始する。現在の会話が Orca の Task / Dispatch を受け取った worker なら、割り当てと preamble に従う。

## 担当と既定モデル

| 担当 | モデル | 権限 |
|---|---|---|
| 進行・仕様整理 | Claude Code `claude-opus-5-5` | 実行記録と仕様を管理 |
| 実装・修正 | Codex `gpt-6.2-sol` | 許可パスのソースを編集 |
| 独立レビュー | Claude Code `claude-opus-5-5` と Codex `gpt-6.2-sol` | ソース読み取り専用 |
| ブラウザ QA | Codex `gpt-6.1-terra` / `max` | 許可した UI 操作と証拠の保存 |

ユーザーがモデルを指定した場合はその設定を使う。既定モデルが利用できない場合は、欠けている担当と使える代替を示して確認する。起動時はモデル、明示した推論強度、workspace、権限を起動結果とセッションの表示で照合する。

## Claude に進行を引き継ぐ

1. タスク文書、対象 repo、Orca workspace、適用される規約を特定する。起動元と対象の workspace を照合し、既存の未コミット変更が重なる場合は作業範囲を確認する。
2. [Orca の CLI ガイド](https://orca.dev/docs/cli/overview) と [実行手順](references/runtime.md) を使う。現在のセッションが進行役の Claude Code でなければ、対象 workspace に専用の Claude Code セッションを起動し、タスク文書・対象パス・規約・このスキルの場所・許可範囲を渡す。Claude が返した引き継ぎ確認を起動結果と照合する。引き継ぎ元は worker を起動しない。
3. Claude は利用者に見える結果、運用への影響、変更範囲、必須チェック、観察可能な受け入れ条件を整理する。ブラウザ QA の対象と必須ケースもここで決める。その内容を仕様書に固定し、対象の版を示してユーザーの承認を得る。承認までは Run・worker・実装を開始しない。引き継ぎ確認と仕様承認の詳細は [実行手順](references/runtime.md) を参照する。

## 候補を実装・検証する

1. **Codex が実装する。** ソースを書ける worker は対象ごとに一人。対象 workspace、起点と既存変更、編集可能パス、受け入れ条件、必須チェックを Task に含める。実装開始前に [checkout のロック](references/runtime.md#checkout-のロック) を取得し、別 Run の実装との重複も防ぐ。
2. **Claude と Codex が独立レビューする。** 実装者と別の新しいセッションを使う。両者に同じ候補と仕様を渡し、最初の報告まで相手の結論を共有しない。レビュー担当のソース編集は許可しない。食い違いはコード・仕様・検証結果で確認し、重大な未解決事項を残す。修正が必要ならソースを担当する Codex に戻す。
3. **別の QA 担当が操作する。** ブラウザ QA が必要な場合は、[Orca QA](../orca-qa/SKILL.md) の手順を確認し、候補が動く環境・専用ページ・テストデータ・必須ケースを渡す。ブラウザの観測範囲を超える必須条件は、その対象を実際に検証できる環境で確認する。
4. **Claude が結果を照合する。** 実行前後の checkout を比較して許可範囲を守れているか確認し、必須チェック・独立レビュー・QA の証拠を同じ候補の版に紐付ける。修正後は必要な検証をやり直す。

## 復帰と終了

- Run ID、対象 workspace、仕様、候補、Task / Dispatch、証拠の場所、未解決事項を記録する。中断から戻るときは、記録と現行の候補、Orca 上の稼働状態を照合してから再開する。
- 既定の上限は4候補。最後の候補に重大な指摘・必須チェック失敗・必須 QA の FAIL が残った場合は、そこで止める。上限や中断時は最新候補の検証結果、稼働状態が不明な担当、残った作業を報告する。起動失敗の再実行は既存の Dispatch と残存リソースを確認してから判断する。
- 必須チェックと必須 QA が満たされ、重大な指摘が解決し、担当の結果を確認してから成功とする。コミット、push、PR、デプロイには別の依頼または既存の明示的な許可を適用する。
