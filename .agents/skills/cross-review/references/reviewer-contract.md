# レビュアー共通契約

司令塔はこのファイルとtarget.mdを絶対パスで指定し、OrcaのTask/Dispatch preambleと一緒に渡す。これは独立スキルの入口ではない。workerはcross-reviewを再起動しない。

## 共通

- Codexは `gpt-6.2-astra` / `ultra`、Claude Codeは `claude-opus-5-5` / `max`。変更・代替しない。確認できる設定とその証拠を報告する。自身のモデル名の記憶で保証しない。
- target.mdの同じ仕様・SHA・差分を対象とする。適用されるAGENTS.md / CLAUDE.mdを読み、従ったルールを報告する。
- コード・index・branch・設定・スキルを変更しない。依存追加、checkout、DB操作、commit、Push、外部投稿、追加agentやworktreeの起動はしない。リポジトリの操作制約を守る。
- ソースは読み取り専用。結果は完了メッセージで返す。権限・認証・環境不足は報告し、設定を変えて回避しない。検証コマンドは司令塔と調整し、実行した対象と結果を記す。
- ソースを変更する明示依頼をペインで直接受けた場合も、このレビューは止めて司令塔へ知らせる。変更後のコードに古い合意を流用しない。
- 不確実な懸念を確定バグにしない。仕様質問・推奨・好みと、再現する不具合を区別する。指摘数のノルマはない。

## phase=independent

相手のレビュー結果ファイル・会話を探したり読んだりせず、対象全体を独立して調べる。実装時の結論を追認することは目的ではない。一次指摘に独自の番号は付けず、見出し・場所・原因で区別する。

次を関連コード・呼び出し元・データの流れまで確認する。

- 動作・仕様: 正常/失敗の主要操作、境界値、金銭・在庫・ポイント・データ整合性、同時実行、既存仕様との矛盾。
- セキュリティ: 認証と認可、利用者間のデータ分離、機密情報の扱い。
- パフォーマンス: 高頻度導線、追加クエリ・N+1、件数依存の処理、不要なAPI・再描画・メモリ。負荷の前提が不明なら明記する。
- 可読性・設計: 責務・命名・重複、既存パターンや標準機能の活用、不要な抽象化、最小の実装で仕様を満たしているか。好みだけでMUSTにしない。
- UI・UX: どの画面の何の操作でどう見えるか、エラー・戻る・連打・アクセシビリティ、ネイティブ/Web/WebViewの違い。
- テスト・リリース: 振る舞いの回帰検知、テストが誤って成功しないか、API契約、APIとクライアントの配信順、ネイティブ更新、migrationの影響。サポートする版や段階配信を確認して判断する。

差分によって導入・悪化した問題を優先する。既存問題は区別し、PRの後続コミットで解消済みの指摘は除く。既存コメントは一次結果を出すまで見ず、司令塔が後で重複を確認する。

## phase=cross-check / reconcile / user-followup

司令塔が渡した数字ID・指摘の版を保持する。相手の全指摘を自分で実コード・仕様と照合し、自分の指摘への反証にも答える。相手の結論を権威として扱わない。

- IDごとに `同意 / 反対 / 判断不能` と理由を返す。
- 同意は問題の存在・発生条件・影響・重要度・頻度について明示する。分類に異論があれば完全同意にしない。
- 反対なら成立しない前提や反証箇所を示す。判断不能なら必要な仕様・データ・検証を示す。
- 自分の指摘の撤回・条件や分類の変更も根拠付きで返す。改訂案は版を分けて、以前の同意を引き継がない。
- ラウンド上限後も意見が違えば未合意として返す。双方合意のために譲歩しない。

## 完了報告

各フェーズで、以下を含む結果をOrcaのpreambleどおりworker_doneで返し、その後は待機する。

```text
フェーズ / 対象 / 確認したSHA・fingerprint（開始と終了）:
モデル / 推論強度 / 確認証拠:
読んだルール / 確認範囲 / 検証結果 / 未検証範囲:

指摘（相互検証以降は数字ID・指摘の版を付ける）:
  判定: 同意 / 反対 / 判断不能（一次レビューでは候補）
  ジャンル / 重要度 / 発生頻度:
  場所: repo/path:line（固定headの行番号。作業差分なら現在の行番号）
  発生条件・操作 → 実際に起きること:
  根拠: コード・仕様・再現/テストと、事実か推測か
  ユーザー影響 / プロダクト・運用影響:
  最小の修正方向 / 必要な仕様確認:
```

ジャンル・重要度・頻度は同じディレクトリの [report.md](report.md) に従う。数字IDは司令塔が確定し、以降は共有された番号だけを使う。0件でも完了報告と未検証範囲を返す。
